# ClawBrain 核心循环

ClawBrain 不能只是很多脚本的集合。

它的核心应该是一条稳定主循环：

1. 我现在要达成什么目标？
2. 当前最小动作是什么？
3. 做完以后有什么证据？
4. 结果好不好？
5. 下一步继续、改方向，还是停止？

## 系统分工

ClawBrain 自己应该沉淀：

- 流程整合
- 判断逻辑
- 证据记录
- 检查点复盘
- 面向客户的交付包装

优先接入成熟工具：

- 爬取工具
- 转写工具
- 模型接口
- 账号管理
- 浏览器自动化
- 文件转换

不要为了证明能力从零重造底层轮子。

## 检查点

监督系统不需要实时盯每一个动作。

更现实的做法是分段检查：

- 任务开始前写清楚目标。
- 每个关键步骤后保存证据。
- 每跑一小段就检查一次。
- 错了就回滚、换工具、缩小动作或换方向。
- 不等整个任务做完才复盘。

适合检查的证据：

- 文件是否生成。
- 客户是否真实触达。
- 邮件是否发出。
- 曝光是否达到最低量。
- 有没有咨询。
- 有没有付款。
- 有没有用户反馈。

## 现在的代码落点

- `task_contract.py`：每个任务开始前写清目标、阶段、最低验证量、预期证据、工具策略和安全边界。
- `decision_contract.py`：自主决策规则、最低验证量、安全门、工具策略。
- `cycle_checkpoint.py`：主循环检查点日志。
- `core.py`：正式主循环，执行前拦截风险动作，执行后记录检查点。
- `brain_v2.py`：把这些规则注入大脑上下文。

## 给普通用户的体验目标

用户只需要说目标。

系统应该自动完成：

- 拆出当前最小动作。
- 调用合适工具。
- 保存证据。
- 判断结果。
- 决定下一步。
- 关键风险动作前问用户。

如果用户看不懂一堆脚本，也能使用这个系统。
