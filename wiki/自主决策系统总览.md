# 自主决策系统总览

结论：Claw-brain 的自主决策系统已经有主体框架。现在最重要的是把“大脑怎么想、怎么执行、怎么记忆、怎么纠错、什么时候问人”固定下来，避免每次新项目都重新摸索。

## 一句话定义

自主决策系统不是单次聊天。

它是一个循环：

```text
目标 -> 思考 -> 决策 -> 执行 -> 观察结果 -> 写入记忆 -> 再决策
```

目标是让系统少等人指令，自己把事情往结果推进。

## 核心文件

| 文件 | 作用 |
| --- | --- |
| `autonomous_system.py` | 大脑主提示词、决策格式、OpenClaw 执行桥接、基础记忆 |
| `core.py` | 真正的运行循环，负责状态、失败处理、市场评估、用户反馈注入 |
| `worker.py` | 后台执行进程，负责长期跑任务，不堵住 Web 页面 |
| `web_console.py` | 控制台页面和 API，负责启动、停止、继续任务、管理凭据 |
| `vector_memory.py` | 语义记忆，按意思找历史经验 |
| `self_heal.py` | 执行失败后的截图诊断和自动重试 |
| `critic.py` | 连续失败时的独立诊断，防止 Brain 自己绕圈 |
| `task_manager.py` | 目标和任务管理 |
| `credential_store.py` | 账号、密钥、平台凭据管理 |
| `brain_modules/planner.py` | 计划、阶段、待办、状态模型 |
| `brain_modules/memory_v2.py` | 分层记忆：短期、压缩、反思 |
| `brain_modules/feedback.py` | 用户评价和纠偏沉淀 |

## 当前已经具备的能力

- 能接收一个大目标。
- 能让 Brain 输出下一步动作。
- 能把动作交给 OpenClaw 执行。
- 能把成功和失败写入记忆。
- 能在 Web 控制台里启动、停止、继续任务。
- 能后台跑 Worker，避免前台页面卡死。
- 能保存 session，方便继续上次任务。
- 能接收用户中途反馈，并注入下一轮决策。
- 能在连续失败时调用 Critic 做外部诊断。
- 能在部分失败场景里截图自愈。
- 能把产物放到 `outputs/` 并写入清单。

## 还没完全闭环的地方

- Planner 模块已经有模型，但还没有稳定接进主循环。
- MemoryV2 已经有结构，但主系统仍主要用旧版 `Memory`。
- Feedback 模块已经有管理器，但还没有成为每轮决策的强约束。
- 自主决策的“安全边界”还不够明确，比如花钱、发内容、改线上系统、删除数据。
- “什么时候必须问人”需要更硬的规则。
- 产物评估还偏粗，需要更贴近真实商业数据。

## 决策输出标准

Brain 每轮应该只输出结构化 JSON。

必须包含：

```json
{
  "thought": "这轮为什么这么做",
  "observation": "我看到了什么状态",
  "action_to_openclaw": "交给执行层的一句话动作",
  "update_memory": "值得以后复用的经验",
  "system_improvement": "发现的系统问题",
  "question_for_user": "只有需要用户输入时才填",
  "status": "continue|milestone|blocked|need_input"
}
```

重点：

- `action_to_openclaw` 要短，最好 40 字以内。
- `status=need_input` 时，只问当前最关键的问题。
- 遇到可复用经验，必须写 `update_memory`。
- 遇到系统能力问题，写 `system_improvement`。

## 自主程度分级

| 等级 | 含义 | 能做什么 |
| --- | --- | --- |
| L1 | 自动执行 | 人给明确步骤，系统照做 |
| L2 | 自动拆解 | 人给目标，系统拆成步骤 |
| L3 | 自动纠错 | 失败后系统能换方法 |
| L4 | 自动验证 | 系统会用真实数据判断方向 |
| L5 | 自动增长 | 系统能持续获客、交付、复盘、放大 |

当前状态更接近 L3，部分触到 L4。

下一步目标是稳定进入 L4。

## 必须问人的场景

这些场景不能假装自主：

- 需要登录、扫码、验证码。
- 要花钱、充值、下单、开通服务。
- 要公开发布内容。
- 要删除、覆盖、迁移重要数据。
- 要改线上环境。
- 要使用用户私人账号做敏感操作。
- 需要法律、财务、医疗等高风险判断。

问法要短：

```text
我需要你确认：是否允许我现在发布这条内容？
```

## 不应该问人的场景

这些应该自己推进：

- 查资料。
- 读本地文件。
- 写草稿。
- 做测试。
- 生成候选方案。
- 本地新增非破坏性文件。
- 总结运行结果。
- 根据错误日志修复代码。

## 新项目默认流程

涉及 Claw-brain 自主决策的新项目，默认按这个顺序走：

1. 明确目标：目标必须能验证。
2. 列最低验证量：比如 50 次触达、500 次曝光、10 次咨询。
3. 建计划：拆成阶段和待办。
4. 执行第一步：不要只分析。
5. 记录动作：成功、失败、原因都要写。
6. 看真实数据：曝光、点击、咨询、回复、成交。
7. 决定继续、优化、换方向。

## 文件归属建议

- 系统规则放 `wiki/`。
- 新项目模板放 `workspace_templates/projects/`。
- 运行记忆放 `system_memory*.json` 或向量库。
- 任务记录放 `sessions/`、`data/`、`tasks.json`。
- 可交付产物放 `outputs/`。
- 凭据只放 `.env` 或 `credential_store.py` 管理的文件，不写进文档。

## 下一步优先级

1. 把 Planner 接进 `core.py` 主循环。
2. 把 MemoryV2 替换旧版 Memory。
3. 给高风险动作加确认门槛。
4. 把“最低验证量”写入商业类目标默认 prompt。
5. 让 Web 控制台显示：当前目标、当前阶段、下一步动作、验证数据。
