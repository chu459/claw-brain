# 自主决策系统推进清单

结论：下一阶段不要大改。先把现有能力接顺，让它稳定完成“目标 -> 执行 -> 数据 -> 判断”的闭环。

## P0：先保证能稳跑

- [ ] 启动 `python web_console.py` 能打开控制台。
- [ ] 控制台能创建新任务。
- [ ] Worker 能后台运行，不堵住页面。
- [ ] 停止任务后 session 能保存。
- [ ] 点继续执行，能接上上一轮日志。
- [ ] OpenClaw gateway 不可用时，页面给出明确提示。
- [ ] `.env` 缺 key 时，只提示配置，不打印密钥。

## P1：把决策闭环接完整

- [ ] `core.py` 每轮读取当前目标、历史记忆、最新反馈。
- [ ] Brain 每轮只输出规定 JSON。
- [ ] `status=continue` 时执行 `action_to_openclaw`。
- [ ] `status=need_input` 时暂停并只问一个关键问题。
- [ ] `status=blocked` 时停止当前路径，并写明原因。
- [ ] `update_memory` 写入长期记忆。
- [ ] `system_improvement` 写入系统改进文档或改进队列。

## P2：接入 Planner

- [ ] 新任务启动时创建 Plan。
- [ ] Plan 拆成 Phase。
- [ ] Phase 拆成 Todo。
- [ ] 每轮决策前读当前 Todo。
- [ ] 每轮结束后更新 Todo 状态。
- [ ] 阶段完成后自动进入下一阶段。
- [ ] 阻塞时标记 Todo 为 blocked，而不是丢失上下文。

## P3：升级记忆

- [ ] 用 `MemoryV2` 替代旧版 `Memory`。
- [ ] 最近动作进入短期记忆。
- [ ] 可复用经验进入压缩记忆。
- [ ] 失败原因进入反思记忆。
- [ ] 向量记忆只保存有价值内容，避免垃圾记忆越积越多。
- [ ] 记忆要能按当前目标检索，而不是只按时间读取。

## P4：加强自主验证

- [ ] 商业类目标必须自动生成最低验证量。
- [ ] 闲鱼类项目默认至少看 500 次曝光。
- [ ] 邮件获客默认至少触达 50 个客户。
- [ ] 内容号测试默认至少发 3 条内容并看真实互动。
- [ ] 每轮只根据真实动作数据判断，不只看想法。
- [ ] 未跑够验证量时，不允许轻易判定失败。

## P5：安全边界

- [ ] 发内容前问人确认。
- [ ] 花钱前问人确认。
- [ ] 删除文件前问人确认。
- [ ] 改线上系统前问人确认。
- [ ] 登录、扫码、验证码只让用户人工完成。
- [ ] 私密信息不写入普通日志。
- [ ] 失败日志可以写原因，但不能写密钥。

## P6：Web 控制台增强

- [ ] 显示当前 Plan。
- [ ] 显示当前 Phase。
- [ ] 显示当前 Todo。
- [ ] 显示最低验证量和已完成数量。
- [ ] 显示最近 5 条关键记忆。
- [ ] 显示本轮为什么这么决策。
- [ ] 显示是否需要用户确认。

## 推荐开发顺序

1. 先修启动、停止、继续。
2. 再接 Planner。
3. 再替换 MemoryV2。
4. 再做安全确认。
5. 最后优化控制台展示。

## 验收标准

一个新目标输入后，系统应该能做到：

- 自动拆 3 到 5 个阶段。
- 每轮只做一个清晰动作。
- 失败后能换方法。
- 卡住时只问一个关键问题。
- 至少产出一个可检查结果。
- 每次停止后能继续。
- 能说清楚“为什么继续、为什么换方向、为什么停止”。
